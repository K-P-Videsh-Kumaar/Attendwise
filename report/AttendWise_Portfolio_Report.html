01 — Context

Problem, purpose & objectives

AttendWise turns attendance from a static college-portal percentage into a clear, private planning system for students.

Problem statement

Students often discover that an attendance threshold is at risk when there is little room left to recover. Existing portals display historic percentages but do not explain the impact of future choices. AttendWise provides a student-managed planning view without claiming to replace official institutional records.

Six product objectives

1. Secure student access
2. Subject-level targets
3. Accurate class logging
4. Clear risk indicators
5. Read-only scenario planning
6. Practical recovery guidance

02 — System design

Architecture & key rules

Business rules are server-owned. The interface requests validated answers; it never treats browser-side calculation as authoritative.

React + Vite + Framer Motion
↓
FastAPI REST API · /api/v1
↓
Attendance · Planner · Risk service layer
↓
SQLAlchemy models · SQLite

Attendance

A / T × 100

A = attended classes.
T = attended + absent classes.
Cancelled records are excluded.

Recovery

ceil((r × T − A) / (1 − r))

The planner returns zero when on target and handles 100% as a special case.

Read-only guarantee. Scenario inputs return a projection only. No hypothetical value is ever written to the attendance register.
03 / 06
03 — Implementation evidence

Important code excerpts

Centralised attendance calculation

attended = baseline_attended + attended records; total = attended + absent; percentage = round(attended / total * 100, 2) if total else None
The calculation service excludes cancelled classes and produces no percentage when there are no counted classes.

Safe, server-side simulation

subject = owned_subject(subject_id, user, db); before = subject_metrics(subject, db); after = simulate(before, attended, missed); return {"read_only": True, "projections": result}
The endpoint verifies ownership, calculates the result and makes no data write.

Information-led motion

<motion.i initial={{ width: 0 }} animate={{ width: `${percentage}%` }} transition={{ duration: .8 }} />
Framer Motion draws each progress bar to a real value, making the percentage easier to perceive without adding visual noise.

Development approach

Model the domain. Users, subjects and class records use explicit status and duplicate-session rules.

Protect data. Every protected endpoint verifies ownership server-side.

Design for clarity. The interface uses hierarchy, risk colour and restrained motion to make status easy to scan.

Challenges addressed

Learning outcomes

Conclusion
AttendWise meets the MVP goal: students can create subjects, record outcomes, understand risk, preview future attendance and plan recovery. It demonstrates secure backend rules paired with a responsive, refined frontend.
